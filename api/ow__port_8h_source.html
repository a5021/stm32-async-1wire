59/* The byte-read capture path (ow_port_read_data, width==8) stores CCR4's
60 * least-significant byte via the DMA memory-store width. How the offsets are
61 * expressed differs per backend: the basic-DMA backends keep PSIZE=16 (CCR4 is
62 * a 16-bit halfword) and let MSIZE=8 store only the low byte, while the F4
63 * backend runs direct mode with PSIZE=MSIZE=8, so the DMA fetches just the low
64 * byte of CCR4. Both are lossless only while every slot capture stays below
65 * 256 microseconds: the counter runs 0..ARR, so the maximum capture value is
66 * ONEWIRE_ONE_PULSE + ONEWIRE_ZERO_PULSE + ONEWIRE_GUARD_BAND. Enforce this
67 * globally across all backends. */
68_Static_assert((ONEWIRE_ONE_PULSE + ONEWIRE_ZERO_PULSE + ONEWIRE_GUARD_BAND) < 256u,
69 "8-bit read capture (MSIZE=8) would truncate slot durations");

71/* --- OC3 output-compare preload (OC3PE) knob ---
72 * The preload bit in TIM_CCMR2 keeps the active CCR3 stable through a slot:
73 * with OC3PE the value written before CEN only enters the output at the
74 * terminal update event, which is the "line released to idle HIGH in
75 * hardware" guarantee (see README, "Bus Idle Behaviour"). The write/capture
76 * paths that rely on it (capture, read_pair, single-slot write) gate the bit
77 * behind this flag so a bench can sweep OC3PE on/off with
78 * -DOW_PORT_OC3PE=0/-DOW_PORT_OC3PE=1 without editing code. The DMA-fed paths
79 * (feed, write_then_read) leave it off unconditionally: their reload must act
80 * immediately, which preload would break.
81 *
82 * Default 1 (preload on) identical to the historical hard-coded behaviour.
83 *
84 * OW_PORT_OC3PE_ARGS (the CCMR2 bit value OR-ed into the mask at the affected
85 * call sites) derives from it, defined where it is used: ow_port_tim_dma.h
86 * for F0/F1/F3/G0 and ow_port_f4.h for F4, by the same #ifndef pattern as
87 * OW_PORT_IC4F_ARGS. */
