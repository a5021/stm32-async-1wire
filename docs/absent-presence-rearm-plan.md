# Absent-presence reset → DMA rearm: implementation plan (rev 2)

Уточнённый план по находке «reset без ответа → немедленно следующая операция»
и корректности неблокирующего disarm/rearm. Дополняет
`docs/absent-presence-rearm-review.md` после сверки строк и проверки
реализуемости write-gating.

## Статус на 2026-09-30

- Реализовано: edge-API (§1), bounded EN-ack в драйвере F4 + общий хелпер
  `ow_port_dma_disable()` на пяти точках (§2), тесты (§3). Прогон `make test`
  по всем семействам (f0/f1/f3/g0/f4 + f4@180MHz) и firmware-сборки всех
  семейств и `make OW_TARGET=f3` — PASS/успех.
- Док (§5): CHANGELOG (Added + Fixed, включая обоснование «почему .bin-гейт
  неприменим к этому изменению»), переписан `@note` у F4-реарма, раздел в
  HARDWARE-NOTES — готово.
- Осталось: бенч на F446RET6 @180 МГц (§4), результаты — в `docs/bench/` и
  HARDWARE-NOTES.

## Проверенные факты по коду

- Пять точек инлайнового `CCR = 0` в общем ядре подтверждены:
  `port/common/ow_port_tim_dma.h` — 284 (capture), 323 (feed), 430 (read_pair),
  477 и 486 (write_then_read). Каждой предшествует перепрограммирование
  `CPAR/CMAR/CNDTR` (286-288, 325-327, 432-434, 479-481, 488-490) и повторный
  `CCR = ... | EN` (289, 328, 435, 482, 491). Это не F4-специфичная зона риска
  архитектурно, а общий паттерн disarm/rearm.
- F4: `ow_port_dma_rearm()` (`port/stm32f4/ow_port_f4.h:213`) вызывается перед
  репрограммированием на 393, 437, 548, 583-584 (Stream2/Stream4), затем
  `PAR/M0AR/NDTR/CR|EN`.

## Снято: строгий write-gating — непропорционально дорого, а не невозможно

1. В C нет перехвата записи в поле **в текущей архитектуре**. Мок — плоская
   структура; драйвер пишет `OW_PORT_DMA_CAPTURE.CNDTR = count` напрямую, тесты
   и hw_model читают то же хранилище. Гейт «запись при EN==1» реализуем, но
   потребовал бы аксессоров для продакшен-регистрового доступа
   (`ow_reg_write32(&stream->CNDTR, count)`), на которых мок гейтил бы запись —
   это отдельная, гораздо более инвазивная архитектурная правка ради одного
   теста. **Пересмотреть, если появится другая причина для accessor-слоя**
   (трассировка регистровых обращений в другом наборе тестов) — вопрос не
   закрыт навечно.
2. Вариант «лаг выключения как на кремнии» самопротиворечив в шаговой модели:
   время движется только внутри `hw_run_until_uif`/`hw_tim_step`, а они
   выполняются после выхода спин-вейта драйвера. Гейт на стороне ЗАПИСИ
   («отклонить запись, если EN логически ещё 1») этого не требует — он смотрит
   предыдущее состояние в момент вызова аксессора; точка (1), а не (2), —
   фактический барьер.
3. Независимо от (1)/(2): при текущем хранилище CR=0→EN=0 мгновенно, поэтому
   даже неисправленный rearm в модели «корректен» (запись NDTR при EN=0).
   Исправленный и неисправленный драйвер на регистровом уровне неразличимы
   в принципе — это рассуждение достаточное само по себе.

Вывод: тест A останется документирующим (end-to-end спецификация).
Принуждение этой конкретной гонки = ревью фикса + бенч. Формулировка,
зафиксированная в шапке теста: «модель без disable-латентности не различает
фикс/нефикс; write-gating в текущей архитектуре обошёлся бы в accessor-слой
для продакшен-регистрового доступа — непропорционально дорого ради одного
теста, а не невозможно в принципе; если появится другая причина для
аксессоров — пересмотреть».

## План реализации

### 1. Edge-API в модели
`hw_set_capture_edges(n)` в `tests/mock/hw_model.{h,c}`, дефолт `0 = unlimited`,
сброс в `hw_reset_all`. В `hw_run_until_uif`: прерывать цикл захвата при
`op_capture_count >= edges` **до** вызова `dma13_transfer()` (невызов трансфера
оставляет `CNDTR`/`EN` в застрявшем состоянии). В `hw_tim_next_capture_tick`:
`if (cap_done >= edges) return UINT32_MAX;`. Существующие тесты не зовут API → не
меняются.

### 2. Драйвер: bounded EN-ack вместо голого `CR/CCR = 0`
- F4: внутри `ow_port_dma_rearm()` после `CR = 0` — ранний выход при `EN == 0`,
  иначе bounded-цикл до `EN == 0`; сброс флагов LIFCR/HIFCR после.
- Общее ядро: маленький inline-хелпер `ow_port_dma_disable()` (тот же ранний
  выход + guard) на пяти точках `CCR = 0` (284/323/430/477/486), включая feed
  (323/486). Feed никогда не under-run → EN уже 0 → 0 итераций; единообразие
  бесплатно.

### 3. Тесты (после edge-API)
- `test_reset_absent_then_present_no_stale_capture`: absence → канал mid-transfer
  (`CNDTR==1`, `EN` set) → немедленный rearm → второй reset видит ровно 2 свежих
  захвата, presence true, шина released. Плюс `reset_pulses[1] == 0` в
  absent-ветке (после edge-фикса буфер честно хранит занулённый драйвером сэмпл).
- `test_reset_absent_twice_in_a_row`: два absence подряд → `CNDTR` каждый раз 1,
  не накапливается.
- Шапка: зафиксировать, что модель без disable-латентности не различает
  фикс/нефикс; принуждение = ревью + бенч.
- Прогон `make test` по всем семействам + `f4_180mhz`, `make OW_TARGET=f3`.

### 4. Бенч (единственный способ принудить и проверить гонку)
- Ручная, документируемая процедура на F446 @180 МГц: закоротить линию шины на
  GND на окно одного reset (нет rising-ребра → недоукомплектованный/нулевой
  захват, канал остаётся взведённым), убрать КЗ, в том же прогоне проверить
  возврат к 7/7. LA на линию шины; retire `CR.EN` — прошивочным пробником
  (печатный лог чтения `CR.EN` в absent-пути), т.к. на ножку EN не выведен.
- Результат в `docs/bench/` и `port/stm32f4/HARDWARE-NOTES.md`.

### 5. Док
- CHANGELOG: Fixed + пояснение, чем новый wait отличается от удалённого
  (CHANGELOG:160-177) и почему модель его не моделирует.
- Правка `@note` у F4-реарма на честный инвариант.
- Раздел в HARDWARE-NOTES про absent-capture rearm.

## Открытые решения
1. Дроп строгого write-gating (по причинам выше) + фиксация «принуждения =
   ревью + бенч» в шапке теста. **РЕШЕНО** (принято пользователем): walk-back
   зафиксирован как «непропорционально дорого (accessor-слой ради одного
   теста), а не невозможно; пересмотреть при появлении другой причины для
   аксессоров» — формулировка внесена в шапку теста и в этот план.
2. EN-ack на всех пяти точках общего ядра (включая feed, который не under-run)
   или только на capture. **РЕШЕНО**: везде, единообразие бесплатно — реализовано.
