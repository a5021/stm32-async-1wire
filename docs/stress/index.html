Stress test report

DMA feed margin under memory-subsystem load - STM32F030x6

Measured 2026-11-03 at commit 15f77c59 (working tree) on STM32F030x6 (STM32F030x6). Build 0_dma_pressure, pattern 00FFAA550FF03CC3, 64 slots per frame, 100 frames per cell, 512 halfwords per DMA burst.

Summary

No starvation, no corrupt slot, no missing release under the tested loads.
  • Every level x clock cell is clean at the 1 us floor (a 2 us window).
  • cndtr_late is 0 and no DMA error was latched in any cell: not even a queued transfer remained at completion.
  • The load is real: the circular transfer plus the CPU hammer cuts the CPU's SRAM passes at 48 MHz from 3300 to 1700; at 8 MHz from 700 to 300.
  • The 5 us guard is a 6 us window, 3.0x the measured 2 us floor; the library and the DMA priority stay unchanged.

The question was whether memory-subsystem load can delay the CCR3 feed DMA past its slot deadline. On this bench it does not: the wire stayed correct at the timer's smallest valid guard even when the load halved the CPU's own SRAM throughput.

What can go wrong

Each write slot is one TIM1 period. The CC2 compare requests the next CCR3 value from DMA1 channel 3; the update event starts the next slot. The transfer has the window between those two events - guard + 1 microseconds, because the counter runs from 0 to ARR inclusive.

Late transferWhat the wire shows
A transfer past the updatethe slot repeats its previous bit; the decoded pattern changes and a frame can lose the final release.
A transfer inside the next low pulsethe pulse stretches or a second edge appears; the slot no longer matches a '1' or a '0' width.
A transfer never servicedCNDTR stays non-zero at completion and the line can be parked low - complete starvation.

The port leaves OC3PE off on the DMA-fed paths, so a late CCR3 write acts immediately instead of waiting for an update: the failure can appear inside the current slot, not only at the next one.

Rig and method

examples/0_dma_pressure transmits a fixed 8-byte pattern (64 slots plus the trailing release) back to back, with a selectable load beside the bus. The bench is STM32F030x6; D0 is the 1-Wire line on PA10. The capture runs at 4.0 MS/s and the firmware is flashed halted, reset by the harness, so only the intended run is judged.

The first slot of a frame is armed by a register write, not by the feed DMA: its width includes the CPU gap between enabling OC3 and starting the timer (about 1 us at 48 MHz, 7 us at 8 MHz). The check skips that slot's width and the first period of each frame. Guard 0 is not an operating point: CC2 then coincides with the update and the release write produces a spurious end-of-frame pulse.

CPU contention

The circular transfer is not free: it competes with the CPU for SRAM. These are the CPU-side passes completed while the bus was running, at the default guard.

48 MHz - level 1 (CPU only)3300
48 MHz - level 5 (circular + CPU)1700
8 MHz - level 1 (CPU only)700
8 MHz - level 5 (circular + CPU)300

Yet the feed met the same 2 us floor in both cases. The load shortened the CPU's own memory work without shortening the DMA's deadline.

Interpretation

  • No wire-visible slip at the 2 us floor on either clock, under any load level.
  • cndtr_late = 0 everywhere: every feed transfer was serviced before completion, including the final release.
  • The load is real, not a no-op: the circular DMA visibly cuts the CPU's SRAM passes (see the chart above), and the finite-burst levels restart the channel hundreds or thousands of times per run.
  • The 5 us guard is a 6 us window. Even at the 2 us floor the wire stayed clean, so this part does not need a larger default and the library keeps its default DMA priority.

Caveats

  • Equal priority only. Every load channel stays at the default DMA priority. An application channel with PL > 0 is a different arbitration case and is not covered by this run.
  • F0 only. The generator is implemented for the F0 backend (STM32F030x6). F4 streams and H5/H7 GPDMA have different arbitration and need their own run.
  • One part, one bench, write-only. The pattern is not a 1-Wire transaction and the attached devices are never addressed (no reset), so the measurement is the master's timing, not a protocol exchange.
  • Timer floor. The 1 us timer cannot resolve a guard below 1; the report therefore says "a 2 us window was enough", not "the latency is exactly 1 us".

The matrix needs an fx2lafw logic analyzer and an ST-Link; it prints SKIP when either is missing. A full 12-cell run takes a few minutes because every cell is rebuilt and flashed.
